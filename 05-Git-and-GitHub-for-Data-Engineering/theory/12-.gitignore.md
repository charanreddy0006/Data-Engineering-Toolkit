# .gitignore

## 1. Introduction

`.gitignore` is a configuration file that tells Git which files and directories should not be tracked.

Data Engineering projects often generate temporary files, logs, virtual environments, credentials, cache files, and local datasets.

These files should usually not be committed to a Git repository.

## 2. Why .gitignore Is Important

Without `.gitignore`, a project may accidentally commit:

```text
.env
passwords
API keys
__pycache__/
*.log
virtual environments
large datasets
temporary files
```

This can create security, storage, and maintenance problems.

## 3. Creating .gitignore

Create the file in the repository root:

```text
project/
├── .gitignore
├── README.md
├── src/
└── tests/
```

## 4. Basic Syntax

Ignore a specific file:

```text
.env
```

Ignore a file type:

```text
*.log
```

Ignore a directory:

```text
logs/
```

Ignore Python cache:

```text
__pycache__/
```

## 5. Python Project

A Data Engineering Python project may use:

```text
__pycache__/
*.pyc
.venv/
venv/
.env
```

Example:

```text
vehicle-pipeline/
├── src/
├── tests/
├── .venv/
├── .env
└── .gitignore
```

Only the required project files should be committed.

## 6. Environment Files

Environment files often contain sensitive configuration:

```text
DATABASE_HOST=localhost
DATABASE_USER=admin
DATABASE_PASSWORD=secret
```

Therefore:

```text
.env
```

should normally be ignored.

## 7. Logs

Pipeline logs can become very large:

```text
logs/
*.log
```

Example:

```text
logs/
├── airflow.log
├── pipeline.log
└── ingestion.log
```

These should generally not be committed.

## 8. Large Datasets

Raw datasets can be extremely large.

Instead of committing:

```text
data/raw/
```

the repository can contain:

```text
data/
├── README.md
└── sample/
```

The README can explain how to obtain the real dataset.

For large versioned data, technologies such as Git LFS or dedicated object storage may be more appropriate.

## 9. Data Engineering Example

A project might use:

```text
vehicle-pipeline/
├── src/
├── sql/
├── dags/
├── tests/
├── data/
├── logs/
├── .env
└── .gitignore
```

A suitable `.gitignore` could contain:

```text
.env
.env.*
__pycache__/
*.pyc
.venv/
logs/
*.log
data/raw/
data/processed/
```

## 10. Checking Ignored Files

Use:

```bash
git status
```

To see whether a particular file is ignored:

```bash
git check-ignore -v .env
```

## 11. Already Tracked Files

`.gitignore` does not automatically remove a file that Git is already tracking.

For example:

```bash
git add .env
git commit -m "Add configuration"
```

Adding `.env` later to `.gitignore` does not remove it from Git history.

Remove it from tracking:

```bash
git rm --cached .env
```

Then commit:

```bash
git commit -m "Stop tracking environment configuration"
```

If a secret was already pushed, simply removing the file is not enough. The exposed credential should be rotated immediately.

## 12. Negation

You can ignore a directory but keep a specific file:

```text
data/*
!data/README.md
```

This keeps documentation while ignoring the actual data.

## 13. Best Practices

- Always create `.gitignore` early.
- Never commit secrets.
- Ignore generated files.
- Ignore local environments.
- Avoid committing huge datasets.
- Keep sample datasets when useful.
- Review `git status` before committing.
