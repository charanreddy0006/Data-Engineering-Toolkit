# 23 — Streaming Data Lake Pipeline

## Architecture

```text
Vehicle
 |
 v
Kafka Producer
 |
 v
Kafka Topic
 |
 v
Spark Streaming
 |
 +--> Checkpoint
 |
 v
Data Lake
```

## Important Concepts

### Event Time

The timestamp generated by the source event.

### Processing Time

The time at which the processing system handles the event.

### Watermark

A mechanism that allows a streaming system to wait for late events while
still making progress.

### Checkpoint

Stores progress and state required to recover from failure.

## Automobile Example

A vehicle can produce speed and battery events every few seconds. Kafka buffers
the event stream while Spark processes the data and writes optimized files to
the lake.

## Main Challenge

Streaming systems must handle duplicates, failures, late events, schema
changes, and backpressure.
