# Data Warehousing - Interview Questions

## 1. Beginner Questions

### Q1. What is a data warehouse?

A data warehouse is a centralized analytical data platform designed to store integrated, historical, and structured data for reporting and analysis.

### Q2. What is OLTP?

OLTP stands for Online Transaction Processing.

It supports operational transactions such as:

```text
INSERT
UPDATE
DELETE
```

### Q3. What is OLAP?

OLAP stands for Online Analytical Processing.

It supports analytical operations such as:

```text
GROUP BY
JOIN
AGGREGATION
REPORTING
```

### Q4. OLTP vs OLAP?

| OLTP | OLAP |
|---|---|
| Transactions | Analytics |
| Current data | Historical data |
| Many small operations | Large analytical queries |
| Normalized models | Dimensional models often used |

### Q5. What is ETL?

ETL means:

```text
Extract
Transform
Load
```

### Q6. What is ELT?

ELT means:

```text
Extract
Load
Transform
```

### Q7. What is a fact table?

A fact table stores measurable business events.

Example:

```text
fact_sales
```

### Q8. What is a dimension?

A dimension stores descriptive information.

Example:

```text
dim_customer
dim_product
dim_date
```

### Q9. What is a star schema?

A star schema contains a central fact table connected to dimension tables.

```text
Dimensions
    |
    v
Fact Table
    |
    v
Analytics
```

### Q10. What is a snowflake schema?

A snowflake schema normalizes dimensions into multiple related tables.

## 2. Intermediate Questions

### Q11. What is grain?

Grain defines exactly what one row in a fact table represents.

Example:

```text
One row = One vehicle sale
```

### Q12. Why define grain first?

Because measures, keys, joins, and aggregation depend on the grain.

### Q13. What is a surrogate key?

A surrogate key is a warehouse-generated identifier.

Example:

```text
customer_key = 101
```

### Q14. Natural key vs surrogate key?

Natural key comes from the source.

```text
customer_id = C001
```

Surrogate key is generated by the warehouse.

```text
customer_key = 101
```

### Q15. What is SCD?

Slowly Changing Dimension describes techniques for handling dimension changes over time.

### Q16. SCD Type 1?

Overwrite the existing value.

```text
Rajkot -> Ahmedabad
```

Old value is lost.

### Q17. SCD Type 2?

Create a new version and preserve history.

```text
Rajkot
2025-2026

Ahmedabad
2026-
```

### Q18. What is a data mart?

A data mart is a business-focused analytical dataset.

Examples:

```text
Sales Mart
Finance Mart
Marketing Mart
```

### Q19. What is a staging area?

A temporary or intermediate area used during data ingestion and transformation.

### Q20. What is a data lake?

A data lake stores large amounts of data, often in raw and processed forms.

### Q21. Warehouse vs data lake?

Warehouse:

```text
Structured
BI-oriented
SQL-focused
```

Lake:

```text
Flexible
Large-scale
Multiple formats
```

### Q22. What is a lakehouse?

A lakehouse combines data lake storage with warehouse-style management and analytics.

### Q23. What is partitioning?

Partitioning divides data into logical sections.

Example:

```text
year=2026
month=08
```

### Q24. Why partition?

To reduce the amount of data scanned.

### Q25. What is indexing?

An index provides a data structure that can speed up certain queries.

### Q26. What is clustering?

Clustering organizes data according to selected columns or keys to improve data skipping or access efficiency, depending on the warehouse.

### Q27. What is a materialized view?

A materialized view stores the result of a query for faster repeated access.

### Q28. What is data lineage?

Lineage shows where data came from and how it was transformed.

```text
Source
 |
 v
Pipeline
 |
 v
Warehouse
 |
 v
Dashboard
```

### Q29. What is metadata?

Metadata is information about data.

Examples:

- Column name
- Data type
- Owner
- Source
- Description

### Q30. What is CDC?

CDC means Change Data Capture.

It identifies changes from source systems.

### Q31. What is incremental loading?

Loading only new or changed data rather than rebuilding the entire dataset.

### Q32. What is full loading?

Replacing or rebuilding the complete target dataset.

### Q33. What is data quality?

Data quality measures whether data is accurate, complete, consistent, valid, unique, and timely.

### Q34. What is data freshness?

The amount of delay between source data availability and warehouse availability.

### Q35. What is schema evolution?

Changes to the structure of data over time.

Examples:

```text
New column
Column rename
Data type change
```

### Q37. How would you process billions of records?

Use:

- Partitioning
- Distributed processing
- Columnar storage
- Incremental processing
- Parallelism
- Query optimization

### Q38. How do you handle duplicate records?

Use:

- Business keys
- Event IDs
- Deduplication logic
- Window functions
- Merge/upsert strategies

### Q39. How do you handle late-arriving data?

Options:

- Watermarks
- Late-arrival queues
- Reprocessing
- Backfill jobs
- Dimension lookup strategies

### Q40. How do you optimize a slow query?

Steps:

```text
Check Query Plan
 |
 v
Check Scan Size
 |
 v
Check Joins
 |
 v
Check Partitions
 |
 v
Check Data Skew
 |
 v
Optimize
```

### Q41. How do you handle schema changes?

Use:

- Schema contracts
- Versioning
- Compatibility rules
- Validation
- Migration procedures

### Q42. How do you ensure pipeline reliability?

Use:

- Retries
- Idempotency
- Checkpoints
- Monitoring
- Alerts
- Data quality tests

### Q43. What is idempotency?

An operation is idempotent when repeating it produces the same intended final result.

Important for retries.

### Q44. What is data skew?

Uneven distribution of data across partitions.

```text
P1 = 10 GB
P2 = 10 GB
P3 = 500 GB
```

### Q45. How do you handle data skew?

Possible approaches:

- Better partition keys
- Salting
- Pre-aggregation
- Adaptive execution

### Q46. What is partition pruning?

The query engine skips partitions that cannot contain relevant records.

### Q47. What is predicate pushdown?

Filters are applied as close to the storage layer as possible to reduce data read.

### Q48. Why use Parquet?

Because it supports:

- Columnar storage
- Compression
- Predicate pushdown
- Column pruning

### Q49. Why avoid SELECT *?

Because it may read unnecessary columns and increase cost.

### Q50. What is a slowly changing dimension?

A dimension whose values change over time.

### Q51. Explain Type 2 SCD implementation.

Common columns:

```text
customer_key
customer_id
city
effective_from
effective_to
is_current
```

### Q52. What is a degenerate dimension?

A dimension attribute stored directly in the fact table without a separate dimension table.

Example:

```text
invoice_number
```

### Q53. What is a conformed dimension?

A dimension shared consistently across multiple fact tables.

Example:

```text
dim_date
```

used by:

```text
fact_sales
fact_service
fact_telemetry
```

### Q54. What is a factless fact table?

A fact table that records events or relationships without numeric measures.

Example:

```text
student_course_attendance
```

### Q55. What is a snapshot fact table?

A fact table that records state at regular intervals.

Example:

```text
daily_inventory_snapshot
```

### Q56. What is an accumulating snapshot?

A fact table that tracks a process through multiple milestones.

Example:

```text
Order Created
Packed
Shipped
Delivered
```

### Q57. How do you secure a warehouse?

Use:

- RBAC
- Least privilege
- Encryption
- Network controls
- Masking
- Auditing
- Monitoring

### Q58. How do you protect sensitive columns?

Use:

- Masking
- Encryption
- Restricted views
- Column-level permissions

### Q59. How do you recover from accidental DELETE?

Possible process:

```text
Detect
 |
 v
Identify recovery point
 |
 v
Restore / Time Travel
 |
 v
Validate
 |
 v
Resume
```

### Q60. What is RPO?

Maximum acceptable data loss.

### Q61. What is RTO?

Target maximum recovery time.

### Q62. Backup vs replication?

Backup provides historical recovery copies.

Replication maintains another copy, often for availability.

Replication alone should not replace backups.

### Q63. How do you reduce warehouse cost?

Use:

- Partition pruning
- Column selection
- Incremental loads
- Compression
- Appropriate compute
- Query optimization
- Storage lifecycle policies

### Q64. How do you monitor a warehouse?

Monitor:

- Query latency
- Failed jobs
- Data freshness
- Storage
- CPU
- Memory
- Cost
- Data quality

## 4. Scenario-Based Questions

### Q65. Dashboard became slow. What do you check?

```text
Query Plan
Scan Size
Joins
Partitions
Indexes / Clustering
Concurrency
Warehouse Resources
```

### Q66. Daily ETL takes 8 hours. How do you improve it?

Consider:

```text
Full Load
   |
   v
Incremental Load
```

Then optimize:

- Parallelism
- SQL
- Partitions
- Source extraction
- Transformations

### Q67. Duplicate sales appeared.

Check:

- Source duplicates
- Join multiplication
- Retry logic
- CDC logic
- Business keys

### Q68. Warehouse data is missing.

Check:

```text
Source
 |
 v
Ingestion
 |
 v
Staging
 |
 v
Transformation
 |
 v
Warehouse
```

Find the first failed layer.

### Q69. Data is fresh in source but stale in warehouse.

Check:

- Pipeline schedule
- Failed jobs
- Queue time
- Source extraction
- Transformation
- Load status

### Q70. One query consumes all warehouse resources.

Use:

- Workload management
- Query limits
- Resource isolation
- Query optimization
- Materialized summaries

## 6. Final Interview Advice

When answering architecture questions:

1. Clarify requirements.
2. Identify sources.
3. Define ingestion.
4. Define storage.
5. Design data model.
6. Explain transformations.
7. Add quality checks.
8. Add security.
9. Add monitoring.
10. Explain scalability and cost.
