# Data Warehousing - Advanced Example

## 1. Project

Build a production-inspired automotive data platform.

## 2. Architecture

Sales

## 4. Streaming

Telemetry events are sent continuously.

```text
Vehicle
 |
 v
Producer
 |
 v
Kafka Topic
```

## 5. Batch Sources

Sales and service systems may be extracted periodically.

```text
OLTP
 |
 v
CDC / Batch
 |
 v
Lake
```

## 6. Data Lake

Store raw events:

```text
raw/
 |
 +-- telemetry/
 +-- sales/
 +-- service/
```

## 7. Spark Transformation

Spark can process large datasets.

Concept:

```python
df = spark.read.parquet("raw/telemetry")

clean = df.filter(
    df.vehicle_id.isNotNull()
)
```

## 8. Warehouse

Curated tables:

```text
fact_telemetry
fact_sales
fact_service
```

Dimensions:

```text
dim_vehicle
dim_customer
dim_dealer
dim_date
dim_location
```

## 9. Incremental Processing

Process only new events.

```text
Previous Watermark
        |
        v
New Events
        |
        v
Transform
        |
        v
Warehouse
```

## 10. Data Quality

Checks include:

```text
vehicle_id NOT NULL
event_time NOT NULL
temperature within valid range
battery_level between 0 and 100
```

## 11. Idempotency

Use event IDs to prevent duplicate processing.

```text
event_id
```

should identify one event.

## 12. Late Data

Events may arrive late.

Use:

- Event timestamps
- Watermarks
- Reprocessing
- Backfills

## 13. Slowly Changing Vehicle Dimension

Vehicle attributes may change.

Use Type 2 history where business requirements require it.

## 14. Performance

Use:

- Partitioning
- Columnar storage
- Predicate pushdown
- Incremental transformations
- Appropriate clustering

## 19. Example KPI

Average battery temperature:

```sql
SELECT
    vehicle_key,
    AVG(battery_temperature)
FROM fact_telemetry
GROUP BY vehicle_key;
```
